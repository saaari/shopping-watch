# Walk n Wok (가칭 소소식당, 小小食堂) — 게임 디자인 문서 (GDD)

> repo: `walknwok` / 버전 0.2 (사이클 확정) / 2026-08-11
> 구성 원칙: **사이클(1~5장)이 본체, 세계관(6장)은 오버레이.** 시스템의 판정
> 로직은 전부 사이클 수치에 걸고, 이름·연출만 세계관에서 입힌다.

## 1. 한 줄 컨셉 & 핵심 정체성

**"당신이 실제로 사는 하루가, 바탕화면 속 작은 식당의 재료가 된다."**

앉아서 일하는 시간은 식당의 영업시간이 되고, 밖에서 걷는 시간은 장을 보러 가는
시간이 된다 — 잔잔한 판타지 식당 아이들러.

| 항목 | 내용 |
|---|---|
| 장르 | 코지(cozy) 아이들러 + 삶-데이터 연동 수집/제작 |
| 플랫폼 | **Steam (데스크탑, 메인)** + 모바일 동반 앱 (재료 수집기) |
| 엔진 | Godot 4.x (데스크탑) / 모바일 앱은 추후 결정 |
| 타깃 | 직장인·학생·재택근무자. 컴퓨터 앞에 오래 앉아 있고, 잔잔한 게임을 곁에 두고 싶은 사람 |
| 세일즈 훅 | **"퇴근길이 장보기가 된다"** + "일하는 동안 바탕화면에서 살아있는 식당" |
| 톤 | 따뜻함, 잔잔함, 약간의 판타지. 죄책감 없음 |
| 재미 보장 단위 | 상주 시간이 아니라 **"하루 5~15분의 능동 재미 × 달력 석 달"** |

이 게임의 존재 이유는 "게임이 현실의 나를 움직이게 만드는 순간"이다. 매일 1만 보
강제가 아니다 — 안 걷던 사람이 일주일에 한두 번 "오늘은 좀 걸어볼까" 하게 만들면
이 컨셉은 성공이다.

## 2. 철칙과 설계 원칙 (헌법)

**철칙: 클릭하지 않아도, 걷지 않아도, 켜지 않아도 절대 벌하지 않는다.**
손님이 화내며 나가지 않고, 식당이 망하지 않는다. 방치는 기본값, 개입은 보너스.
이 게임은 "일하는 나를 응원하는 동료"다.

철칙의 하위 원칙 6개 — 이후 모든 시스템 판정은 이 원칙을 참조한다:

1. **불은 절대 꺼지지 않는다.** 잉걸불은 무조건·영원. 한 달을 안 걸어도
   식당은 영업하고 수익이 들어온다.
2. **걷기는 하한 수호가 아니라 상한 개방.** 화력은 벌점이 아니라 "오늘의
   시간표"다. 동기는 감쇠(밀기)가 아니라 초대장(당김)이 만든다.
3. **반사실(counterfactual) 금지.** "안 걸어서 못 온 손님"을 어떤 형태로도
   보여주지 않는다 — 회색 실루엣, 잠금 아이콘, 취소선, "센불이었다면…" 전부
   금지. 예고는 전방(초대)만 하고 후방(놓침)은 절대 보여주지 않는다.
4. **모든 것은 다시 온다 (순환 노선 원칙).** 오늘 놓친 손님·노선·업적은
   일정을 돌아 반드시 재방문한다. 영구 미획득 콘텐츠 없음.
5. **하강은 조용히, 상승은 요란하게.** 화력 하강은 무통지 — 그저 다음날 역이
   조금 한산하다. 상승만 사건(불꽃 연출, 역귀 환호)이다. 게이지 바·스트릭
   카운터 UI 금지 (줄어드는 바는 그 자체가 압박, 스트릭 숫자는 상실 가능 자산).
6. **양방향 무벌.** 안 걷는 것을 벌하지 않듯, 과잉 착석도 보상하지 않는다.
   **자동 마감 금지** — 수익 포화는 보이지 않는 소프트캡(8~10시간, 수치는 튜닝)
   으로 하고, "마감 풍경" 연출은 오직 플레이어가 퇴근 버튼을 눌렀을 때만
   발동한다. 게임이 플레이어보다 먼저 퇴근하는 상태 전이는 존재하지 않는다.

## 3. 플레이어의 하루 — 전체 사이클

### 3.1 세 개의 시계

| 시계 | 흐르는 곳 | 의미 |
|---|---|---|
| **영업 시계** | 데스크탑 세션 (실시간) | 식당이 굴러가는 시간. 손님·조리·이벤트 |
| **수집 시계** | 폰 (백그라운드 누적) | 걸음·맥락이 재료로 증류되는 시간 |
| **부재 시계** | 둘 다 꺼진 시간 | 역귀가 대신 보는 시간 — 요약 1장으로 압축 |

세 시계 어디에서도 잃는 것은 없다. 부재조차 "놓친 시간"이 아니라 "돌아오면
요약과 소소한 수확이 기다리는 시간"이다.

### 3.2 배달 의례 — 상대 위상 규칙

**개봉 대상 = 지난 개점 이후의 삶.** 아침형에게는 "어제의 걸음 → 오늘 아침
개봉"(1일 위상차), 저녁형에게는 "오늘 낮 → 오늘 저녁 개봉". 위상차는 생활
패턴이 정하고, 규칙은 하나다:

- 걷기 재료는 데이터 도착 시각과 무관하게 **"다음 개점 첫차" 또는 "새벽 첫차
  (현지 4~6시)" 중 먼저 오는 쪽에 일괄 배달**된다. 폰 동기화 지연·재전송이
  플레이어에게 보이지 않고, 개점 개봉의 마법 순간이 보존된다. 24시간 켜둔
  머신도 매일 새벽 첫차가 어제를 배달한다.
- 맥락 라벨(시간대·날씨)은 **폰에서 캡처 시점에 확정**한다. 데스크탑 재판정
  금지(시차·기기 시계 불일치 원천 차단).
- 데스크탑에 실시간 걸음 표시 금지 — 현장 채집의 손맛은 폰 쪽에만.

### 3.3 페르소나 4종의 하루

**A. 사무직 직장인 (주 5 출근, 왕복 도보 40분)**

```
07:30 기상 — 폰은 주머니에. 아무것도 안 해도 됨 (수집은 백그라운드)
08:20 출근길 도보+지하철 (~4,000보 · 아침·요일·날씨 태그)
09:00 데스크탑 ON → 개점 리추얼 2~3분 → 이후 보조 모니터/작은 창
10:30 커피 타임에 흘끗 — 그릇이 쌓였네, 설거지 15초
12:00 점심 산책 (+2,000보 · 점심 태그) / 게임엔 정오의 점심 러시
15:00 특별 손님 은은한 알림 → 흘끗, 서빙 돕기 20초
18:00 데스크탑 OFF = 퇴근 버튼 — "다녀오세요!"
18:40 퇴근길 (+4,000보 · 저녁 태그. 비 오면 『빗속의 귀갓길』)
22:00 (선택) 집에서 10분: 정산·단골 쪽지·내일 메뉴 예약
```

하루 능동 개입 5~15분. 필수 접점은 개점 리추얼 하나뿐이며 그마저 안 하면
역귀가 어제 메뉴로 자동 개점한다(직접 하면 그날 메뉴 선택권 — 보너스).

**B. 대학생 (이동 많음, 세션 30분~2시간 조각)**

걸음은 많고(8,000+/일) 세션은 파편. → **영업일은 세션이 아니라 실제 달력의
하루** 단위다. 노트북을 닫으면 역귀 인계, 다시 열면 이어서. 개점 리추얼과
부재 요약은 **달력일 첫 접속에만** — 같은 날 재접속은 역귀의 한 줄("다녀오셨어요")
로 조용히 이어붙인다 (리추얼의 밀도는 희소성에서 나온다).

**C. 재택근무자 (걸음 거의 0, 데스크탑 10시간+)**

이 장르의 실구매층. 걸음이 없어도 식당은 잉걸불로 완결적으로 굴러간다.
화력 문턱은 이 페르소나 기준으로 설계한다 — **산책 한 번(~2천보, 15분)이
당일 저녁 눈에 보이는 변화**를 만든다 (§4.1). 게임의 건강 넛지가 가장 필요한
사람에게 가장 잘 작동해야 한다.

**D. 주말·휴가 (데스크탑 없이 걷기만)**

주말에 몰아 걸은 대량 재료가 월요일 개점을 풍성하게 — 출근의 작은 낙.
대량 배달은 요약 우선("닷새의 여정이 담긴 상자 셋"), 개별 개봉은 선택
(개봉이 인벤토리 노동이 되지 않게). 여행의 맥락 재료는 플레어 큐(§4.1)로
복귀 후 일주일의 여운이 된다. 여행에서 돌아온 날의 개점이 이 게임 최고의
순간이 되도록 설계한다.

### 3.4 데스크탑 세션 구조

**① 개점 리추얼** (달력일 첫 접속, 2~3분 — 하루의 밀도 최고점). 4슬롯:

```
재료 상자 개봉 → 편지꽂이 (엽서·정산·쪽지) → 오늘의 시간표 → 메뉴 걸기
```

30일째에도 기대되게 하는 5장치:

1. **개점 = 어제 건 베팅들의 회수 시간.** 걸어둔 메뉴가 통했나, 응한 초대장에
   특급이 왔나, 배웅한 손님의 엽서가 왔나 — 개봉의 기대를 RNG가 아니라
   **플레이어 자신의 어제 행동**이 만든다. 신선도가 참여도에 비례해 자가 조절
   되는 구조적 해답.
2. **해석의 변주.** 같은 5,000보도 역귀의 일기 한 줄이 다르게 읽는다 —
   "어제는 바람이 등을 밀어주는 날이었죠." (날씨×계절×걸음 패턴 문장 템플릿)
3. **이변은 확률이 아니라 보장 스케줄러로.** 독립 확률은 뭉침과 가뭄을 만든다.
   소형 이변(역귀의 습득물, 손님의 유실물) 주 1~2회 보장, 중형(낯선 노선 임시
   정차) 격주 1회, 대형은 절기에 도킹. 유실물 반환 의뢰 → 그 손님 재방문
   보장이 최고 효율의 서사 훅.
4. **우편의 도킹.** 엽서·편지의 도착 시점을 개점 리추얼로 모은다(밤새 온 우편).
5. **포장의 미장센.** 상자 겉모습이 어제의 맥락을 반영 — 비 온 날은 젖은
   신문지, 폭염엔 얼음 두른 상자, 첫눈엔 눈 소복한 뚜껑. 밸런스 영향 0,
   "게임이 내 하루를 봤다"는 감각을 매일 갱신.

**② 영업 중** (수 시간, 방치 + 곁눈질)

- **실시간 미러링** — 게임 하늘이 실제 시간(아침 햇살→노을→밤)과 실제 날씨를
  따른다. 저프레임(8~12fps) 픽셀 애니메이션으로 CPU 초경량.
  시간대별 콘텐츠 밀도는 균등하게(새벽형·주간형 어느 생활패턴도 손해 없게),
  시간대 한정 손님은 본편 도감이 아닌 "여행 기록" 별권으로.
- **개입 3종** (각 5~30초, 순수 보너스): 설거지(그릇 클릭→회전율↑) /
  재료 손질(드래그→다음 요리 가속) / 서빙 돕기(타이밍 클릭→팁). 보상은 수치가
  아니라 눈에 보이는 즉각 피드백(동전이 튀고 손님이 웃는다).
  **하루 상한 8~12회** — 상주 감시가 최적 플레이가 되지 않게. 상한 도달 후엔
  역귀가 "오늘은 제가 할게요"로 자연 흡수.
- **간헐 이벤트** — 시계는 벽시계가 아니라 **"지켜본 시간" 누적**(부재 중 정지,
  접속 중만 진행). 파편 세션 4×30분도 누적 2시간으로 최소 1회 보장, 하루 발생
  수 상한으로 상주 독식 차단. 알림은 은은하게 1회, 무시해도 사라지지 않고 대기.
- **정오의 점심 러시** — 실시간 12시 전후 여행자가 붐빈다. 플레이어 자신의
  점심시간과 동기화된 "흘끗 볼 이유". 밤에 켜면 야간 손님 — 식당이 내 시간대를
  산다.

**③ 퇴근 버튼** — 데스크탑을 끄는 것 = 폐점이 아니라 **역귀에게 인계하고
외출**. 게임이 꺼짐을 축하한다: "다녀오세요! 좋은 재료 부탁해요." 강제 종료도
동일 처리, 잃는 것 0. 끄는 행위에 대한 죄책감 제거 + "이제 걷기 턴" 전환 신호.

**④ 재접속·복귀** — 부재 요약 1장. 부재 중 수익은 화력·부재 길이와 곱셈하지
않는 **고정 편지**(약간의 돈 + 근황 + 단골 쪽지 — "잉걸불이라 2주 부재 수익이
적다"는 가장 안 보이는 곳의 소급 벌이므로 금지). 요약은 메뉴 인과를 문장으로
명시한다("국물 메뉴에 비 맞은 여행자 셋이 내렸어요" — 부재 중에도 미끼 효과가
보이게). 장기 부재 복귀는 디버프 화면이 아니라 연출된 장면: 조용한 역 + 불 쬐는
손님 + 쌓인 편지와 정산 + "돌아왔구나". 그리고 산책 한 번이면 다시 타오른다.

### 3.5 두 모드 선언 — 둘 다 1급 시민

| 모드 | 대상 | 경험 |
|---|---|---|
| **곁눈질 모드** | 보조 모니터·상주 가능한 환경 | 살아있는 창 + 간헐 개입 |
| **체크인 모드** | 회사 PC에 Steam 불가한 직장인 등 | 저녁 30분: 개점 리추얼 + 부재 요약 + 메뉴 + 엽서·의뢰 |

개점 리추얼·부재 요약·메뉴·엽서 스택은 체크인 모드만으로 완결된 게임이 되도록
설계한다. 스토어 문구도 두 모드를 모두 판다 — 곁눈질만 팔면 회사 PC가 잠긴
구매자에게 과대 판매가 된다.

## 4. 시스템 설계

### 4.1 화력 = 시간표 (배율 금지)

화력은 "전반적으로 더 좋아짐"(범용 배율)이 아니다 — 범용 배율은 사람을 걷게
하지 못한다. 화력이 결정하는 것은 **오늘 역에 서는 노선(손님 풀)뿐**이며,
돈·레시피·도감·호감도·확장에는 영향이 없다. 동기는 구체적 초대장이 만든다:
"내일 아침까지 걸으면 특급이 서고, 소문의 눈여우 상인이 온대요."

**4상태와 문턱** (재택 페르소나 기준으로 하향 설계):

| 상태 | 조건 | 서는 노선 |
|---|---|---|
| 잉걸불 | 기본값 (조건 없음, 영원) | 완행(동네 노선) + 잉걸불 손님 |
| 중불 | **산책 한 번(~2천보) → 당일 저녁 즉시** | +급행(계절 노선). "산책 한 번 한 날" |
| 센불 | 롤링 7일 중 4일+ 각 4천보 | +특급(먼 나라 노선). "요즘 꾸준한 사람" — 통근자는 자연 상주 |
| 푸른불 | 맥락 재료 획득 (당일 플레어) | +유령 노선 임시 정차 (맥락 1:1 미러 손님) |

- 통근 직장인은 자연히 센불 상주, 재택은 점심 산책 15분이라는 실행 가능한
  초대에 매일 반응할 수 있다. **저구간 민감도 우선**: 0→2천보의 체감 변화가
  8천→1만보보다 커야 한다.
- **개인화 적응형 문턱 금지** — 나아질수록 기준이 올라가는 러닝머신은 벌의 귀환.
- **감쇠**: 센불 —무활동 3일→ 중불 —추가 4일→ 잉걸불. 주말 이틀 휴식으로는
  단계가 내려가지 않고(압박 하한), 1주 방치는 반드시 화면에 보인다(거울 상한 —
  이보다 느리면 화력은 벽지가 되고 걷기의 효과가 안 비쳐 동기가 소멸).
  ⚠️ 감쇠 속도는 "동기 강제" 노브가 아니라 **"거울의 충실도" 노브**다.
  걷게 만들려고 감쇠를 조이는 순간 벌 모델이 뒷문으로 돌아온다.
- **회복 비대칭 (죄책감의 최종 안전장치)**: 하강은 느리고 조용하게, 회복은
  빠르고 요란하게. 복귀 보너스는 '붙는 속도'지 '주는 양'이 아니다(장기 이탈이
  이득이 되지 않게). 서사: "잉걸불이 남아 있으니 다시 붙는 건 금방이죠."
- **푸른불 = 지속 단계가 아니라 당일 플레어, 큐로 소진.** 맥락 재료(새벽·빗속·
  낯선 동네) 획득마다 큐에 쌓여 **하루 1플레어씩** 유령 노선이 정차한다 —
  여행 5일치 맥락이 복귀 후 일주일의 여운이 된다("이번 주 내내 유령 노선이
  섭니다"). 지속 단계로 만들면 새벽 빗길 반복을 요구하는 번아웃 기계가 된다.
- **잉걸불 손님** = "불 쬐러 오는 조용한 존재". 첫만남은 자연 발생한 잉걸불 날
  **+ 정기 휴업일**(게임 달력의 명절 — 걷기와 무관하게 모두에게 계절당 몇 번
  보장. 복귀 플레어와 겹치면 플레어 우선, 휴업일은 밀림) 양쪽에서 가능. 한번
  만난 뒤에는 화력 무관하게 관계 지속. ("못 걸은 주 전용 손님"은 도감 완성을
  위해 일부러 안 걷는 역설을 만들므로 금지.)
- 화력·기상 조건 손님 도감은 본편 100%와 분리된 **"여행 기록" 별권**으로
  (사막 지역 플레이어의 비 재료 등 기후 편차도 같은 장치로 해소).
- 걸음의 일일 환산 소프트캡 초과분은 **누적 이정비석**(평생 걸음 마일스톤)으로 —
  걸은 것이 버려지는 순간이 없게.
- 표시는 상태 명사만: "오늘의 불: 중불 — 급행이 섭니다." 게이지 바·감소
  애니메이션 금지 (헌법 5). 예고는 상승 방향만 (헌법 3).

### 4.2 재료와 증류

폰이 하루의 활동을 **맥락이 새겨진 재료**로 증류한다. 재료 = 수량(걸음) ×
태그(맥락). 태그 조합이 희귀도를 만든다 — 『비+자정+낯선 동네』는 전설급.

| 데이터 축 | 재료화 |
|---|---|
| 걸음 수 (양) | 기본 수량. 1,000보 단위 (수치는 튜닝) |
| 시간대 | 『자정의 산책』(야식 계열), 『새벽 러닝』(매콤한 볶음 계열) |
| 날씨 | 『빗속의 귀갓길』(국물 계열), 『쾌청한 아침 산책』(샐러드 계열) |
| 요일·계절·기념일 | 주말 재료, 계절 특산, 명절 한정 |
| 걷기 리듬 (케이던스) | 산책(여유) / 빠른 걸음(활기) / 러닝(불꽃) |
| 장소 새로움 (선택, GPS) | 좌표가 아닌 novelty 정도만 — 새 동네 = 특산 재료 |
| 심박 (선택, 웨어러블) | 『폭주하는 심장』 — 희귀 향신료. 있으면 보너스 |

- **기억 각인**: 맥락 재료에 획득 순간이 새겨진다("8월 11일 저녁, 비"). 요리에
  쓰이면 손님이 그 순간을 인용한다 — "이 국물, 화요일 저녁 빗소리가 나는군요."
- **식당 일지** 자동 생성: "8/11: 폭우를 뚫고 온 우산 정령에게 『화요일의
  빗물국』을 냈다." 내 실제 삶이 식당 설화로 번역된 일기 — 스크린샷 공유 자산.
  구현 비용은 텍스트 템플릿뿐.
- 폰을 안 열어 날씨 맥락을 놓친 걸음은 "무맥락 기본 재료(주식 곡물류)"로 —
  여전히 쓸모 있게.
- 재료는 도감에 수집된다. P1은 실데이터 대신 목업 주입(§7).

### 4.3 두 속도의 주방 + 개입

**🐢 방치 (기본값)** — 재료 → (자동) 손질 → (자동) 조리 → 서빙 → 돈.
역귀가 손질·조리·서빙을 담당한다. 느리지만 확실하게.

**⚡ 개입 (보너스)** — §3.4의 3종, 하루 상한 8~12회. 클릭 없이도 절대 벌 없음.

### 4.4 메뉴판 — 하루 한 번의 결정

주방 파이프라인의 유일한 능동 결정. 매일 마감(또는 개점) 때 레시피북에서
**내일 메뉴 3칸** 선택 — 30초. 미선택 시 역귀가 어제 메뉴 유지(무벌).

- **메뉴 = 미끼.** 메뉴 구성이 오는 손님 유형을 편향한다(국물 메뉴 → 비 맞은
  여행자). 화력=노선(누가 지나가나) × 메뉴=취향(누가 내리나)의 2축 필터.
- "내일 비 예보 + 마침 빗길 재료 있음 → 국물을 걸자 → 겸사겸사 나도 우산 들고
  걷자" — 일기예보→메뉴→산책 의도가 정렬되는 고리.
- 철칙 정합: 잘못된 메뉴 = 손님이 '없음'이 아니라 '다름'. 구성만 바뀐다.

### 4.5 손님 — 의뢰·여정·배웅·엽서

- **의뢰 게시판** (재생성 퀘스트 동사): 상시 2~3건, 무기한, 놓치면 순환 복귀
  (헌법 4). 재료 조건은 맥락 조합에서 절차 생성 — "비 오는 저녁의 3,000보".
  매주 "이번 주에 걸어볼 이유"를 자동 공급한다. "요즘 쓸쓸한 맛이 먹고 싶어요"
  → 그런 재료가 나오는 하루를 살아서 구해온다.
- **여정과 배웅**: 이름 있는 여행자는 목적지가 있다(겨울은 남쪽으로, 낡은 신은
  은퇴하러). 잘 먹이면 호감도 숫자가 아니라 **배웅**이 발생한다. 배웅은 방치로도
  느리게 진행되고, 개입·메뉴 적중은 가속이다(철칙 정합 — 개입 필수면 위반).
- **엽서**: 배웅한 손님이 며칠 뒤(실시간 지연 = 세션 간 기대감) 목적지에서
  엽서를 보낸다 — "남쪽에 잘 도착했어요. 그 국밥 덕에." 대합실 지도에 쌓여
  "내 요리가 배웅한 여정의 지도"가 된다. 도착은 개점 리추얼에 도킹.
- **전수 레시피**: 새 레시피의 주 출처는 상점 구매가 아니라 **손님 전수**
  (여행자가 고향 요리를 가르쳐 준다). 레시피가 관계의 보상이 되고, 돈은
  도구·확장·가구에 집중된다. (과할 경우 후퇴선: 기본 구매 + 희귀 전수 혼합)
- **단골**: 특정 요리를 반복 제공하면 단골이 되고 사연이 조금씩 열린다.
  계절 단골은 실제 달력 계절마다 돌아와 지난 만남을 기억한다 — 연 단위 리텐션
  비트. 스토리는 짧은 쪽지·대사 단위, 텍스트 부담 최소, 여운 위주.

### 4.6 경제 — 돈의 사용처 (성장의 세 축)

| 사용처 | 성장 축 | 효과 |
|---|---|---|
| 🍳 주방 도구 | 아이들러 성장 | 방치 속도·효율 (장면형 원칙 적용) |
| 🪑 확장·가구·인테리어 | 꾸미기 | 손님 수, 분위기, 스크린샷 욕구 |
| 📜 (레시피는 전수로 이동) | — | 돈의 역할에서 제외 (§4.5) |

- **장면형 업그레이드 원칙 — 순수 % 업그레이드 금지.** 모든 구매는 보이는
  변화여야 한다: 대합실 난로 → 잉걸불 손님이 오래 머묾, 승강장 등불 → 밤 노선
  정차. 업그레이드가 숫자가 아니라 장면·손님·노선을 해금한다.
- 하루 수익은 보이지 않는 소프트캡에서 포화 (헌법 6 — 좌식 역인센티브 차단).

### 4.6-1 식당 성장 — 다섯 정거장

식당은 **간이역 분식 → 보통역 식당 → 급행 정차역 식당 → 특급 정차역 식당 →
종착역 명물 식당**의 5단계로 자란다. 성장은 화면 그 자체다:

| 단계마다 커지는 것 | 구현 |
|---|---|
| **창이 좌우로 길어진다** | 논리 폭 400→476→552→628→704px (게임 창 자체가 확장) |
| 테이블·좌석 | 1탁 2석 → 5탁 10석 |
| 알바생 (다람쥐) | 3단계 1명, 5단계 2명 — 빈 접시를 치워 나른다 |
| 꾸밈 | 화분 → 램프·그림 → 괘종·모자걸이·엽서 → 어항·갈랜드 (자동 추가) |
| 주방 | 솥 용량 +2접시/단계, 접시 간격 -30초/단계 (같은 걸음으로 더 많이 먹인다) |
| 명성 | 손님 발걸음 +8%/단계 |

- **해금 = 누적 서빙** (20/60/120/200그릇) — 놓칠 수 없고 언젠가 반드시 온다
  (헌법 4). 해금 순간 "목수가 다녀갔어요" 이벤트 (전방 예고), 확장은 코인으로
  구매 (200/500/1,200/2,500 — 돈의 최대 사용처).
- 활기 장치: 식사 중 테이블에 음식 표시, 식사 후 **빈 접시가 테이블에 쌓임**
  (1/3/6단) → 알바생이 순회 수거 (없으면 역귀가 느리게, 클릭 정리는 개입),
  계산 시 +코인 팝업, **점심·저녁 러시** (실시간 12·18시, 손님이 파도로 몰림).
- 시뮬 검증 (3사이클): 5일 만에 5단계 도달 (매일 성장 체감), 러시 때 동시
  손님 최대 8명, 빈 화면 0%, 하루 서빙 79→159 성장 곡선.

2. 엽서 지연 회신 — 주 단위 되돌아옴 훅 (§4.5)
3. 단골 부탁 체인 — bespoke 텍스트는 이 구간에 집중 투자 (첫 단골 등극 Day 4~7,
   부탁 체인이 주 2~6에 걸치도록 배치)
4. **절기 마이크로 비트 — 15일마다** 작은 시간표 변화 + 한정 손님 1 + 대사 몇 줄.
   계절 개편(90일)은 이 사막에 너무 늦다. 절기당 손님 1+문장 몇 개의 경량
   구성이라 1인 개발 예산에 든다.

60h+ 의 역 확장(새 노선 = 새 손님군)은 개발 콘텐츠 소모형이므로 연 1~2회
이벤트로 아껴 쓴다 — 기본 지탱은 사계 순환 + 절기.

### 5.2 달력 = 콘텐츠

**실제 달력이 게임 달력이다.** 계절·명절·기념일이 현실과 동기화 — 콘텐츠를
시간이 공급한다. 겨울 한정 재료·손님은 진짜 겨울에만(놓쳐도 내년에 다시 —
헌법 4). 절기 비트(15일) < 명절 휴업일(계절당 몇 번) < 계절 노선 개편(90일)의
3층 해상도. 1인 개발 예산: bespoke 스토리는 단골 한 자릿수로 한정하고 나머지는
아키타입×계절×노선 조합 생성.

### 5.3 업적 시스템 (~125개)

설계 원칙 4:

1. **허용 3형** — 누적(카운터, 절대 리셋 없음) / 발견(도감 연동) / 순간(특정
   장면의 목격). **금지 3형** — 연속(streak) / 기한(시한부) / 상실 가능.
   모든 업적은 "언젠가는 반드시"가 보장된다 (순환 노선 원칙의 업적 버전).
2. **"하지 않음"이 최적 전략이 되는 업적 금지.** 잉걸불 손님 업적은 정기
   휴업일 경로로 달성 가능해야 한다. "완전 방치의 날"(개입 0으로 하루) 같은
   단발은 철칙 홍보라 좋지만 "30일 무개입" 같은 스케일 금지.
3. **게임 내 표현은 반사실 금지를 따른다** — 회색 실루엣 그리드가 아니라
   **"역장의 기록부"**: 달성한 것만 도장이 찍히고 미달성은 칸조차 없거나 소문

### 5.4 앨범 성장 (프레스티지 없음)

프레스티지(리셋)는 "잃는 경험"이라 철칙 위반 — 사용 불가. 대체 구조:

1. **성장을 스톡 → 앨범으로**: 도감·일지·엽서지도·여행 기록 별권·이정비석.
   숫자는 포화해도 기억은 포화하지 않는다. 콘텐츠의 원천이 플레이어의 실제 삶
   (날씨·계절·여행)이므로 리텐션 엔진은 콘텐츠 볼륨이 아니라 **거울의 충실도**다
   — "비 오는 날은 게임도 달라 보인다"가 유지되는 한 세계는 매일 새롭다.
2. **계절 노선 개편** — 실제 계절마다 시간표 개편 (새 노선, 일부 휴업 — 순환
   원칙으로 복귀 보장), 계절 단골 회귀.
3. **장면형 업그레이드 원칙** (§4.6).

## 6. 세계관 오버레이 — 🍂 환승역 식당

### 6.1 세계관 본문

핵심 질문 **"왜 내 하루가 이 식당의 재료가 되는가?"** 에 대한 답.

정령·신·요괴·계절도 "이동"한다 — 겨울은 남쪽으로, 낡은 신은 은퇴하러. 그 길목의
환승역에 딸린 식당이 무대다. **이 식당의 화덕은 "인간의 이동"을 연료로 탄다.**

- **주제문: "내 평범한 하루가 누군가에겐 진귀한 맛이다"**
  (여행자에게 남의 동네 골목길은 진귀한 맛이다)
- 손님: 매번 새 얼굴(여행자) + 계절마다 돌아오는 단골
- 정서: 여정, 계절감, 만남과 배웅. "잘 먹었어요, 또 지나갈게요"
- **주방 도우미: 낡은 역귀(驛鬼)** — 역무원 겸 홀서빙
- 접근성 각주: 연료의 언어는 "걸음"이 아니라 **"인간의 이동"** — 휠체어·자전거
  등 이동 전반을 포용한다 (§8 산책 수첩 경로 포함)
- 확정 이유 ① "걸음 = 화덕의 연료"가 시스템과 서사를 1:1로 접착 ② 여행자
  설정이 신규 손님 무한 공급을 정당화 ③ "또 지나갈게요"가 순환 노선 원칙
  (헌법 4)을 서사로 공짜로 정당화

**탈락안 기록** — *경계의 식당*(현실↔이세계 틈): 주제문은 좋으나(이식했다)
"하루"를 연료로 삼아 걷기를 특정하지 못함. *꿈결 식당*(잠들지 못하는 존재들):
위로의 정서는 강하나 밤 톤에 갇혀 낮에 켜두는 게임과 어긋남. 공통 약점은
걷기의 서사적 필연성 부재.

### 6.2 시스템:서사 매핑표 — "덧씌움"의 실체

빈 칸이 생기면 "서사 이름이 아직 없는 시스템"이고, 반대로 시스템 없는 서사는
장식 설정이다 — 양쪽 다 이 표에서 즉시 걸러진다.

## 7. 프로토타입 계획

### 검증하려는 것 (우선순위 순)

1. **"일하며 곁눈질하는 식당"이 실제로 기분 좋은가?** (방치+개입의 리듬 —
   화덕·시간표 무대 포함. 무대 없는 검증은 "일반 식당"을 오측정한다)
2. "상황이 새겨진 재료 → 요리" 루프가 수집욕을 자극하는가?
3. 재료를 얻기 위해 현실 행동이 바뀌는가? (실검증은 P2, 기제는 P1에서 스모크
   테스트 — 초대장이 '초대'로 읽히는가 '숙제'로 읽히는가)

### 단계

| 단계 | 내용 | 데이터 |
|---|---|---|
| **P1** | Godot 데스크탑 단독. 아래 스코프 | **목업** (디버그 패널 주입) |
| P2 | 폰 수집기 (걸음) + 릴레이 동기화 + 감쇠·연료 실장 | 실데이터 |
| P3 | 날씨·장소 맥락 확장, 단골 스토리, 위젯화, Steam 준비 | 확장 |

### P1 스코프

- 식당 씬: 주방 + 테이블 2~3개, 손님 자동 방문. **씬 구도는 위젯 비율**(화면
  구석/하단 스트립 — 레이아웃은 나중에 못 바꾼다)
- 자동 파이프라인 + 개입 3종 (하루 상한 포함)
- **화력 4상태 연출 스텁**: 디버그 슬라이더 → 화덕 비주얼 + 시간표 보드 +
  손님 풀 필터만 전환. 잉걸불 상태의 정서 반응(벌로 느끼는가) 관찰 — 이 게임
  최대 설계 리스크(죄책감 프레이밍)의 최저 비용 실인간 테스트
- **메뉴판 3칸** + 미끼 반응
- **초대장 1종 목업** ("내일 비가 온대요. 빗속을 걸으면…" 카드 + "걸었다 치기"
  디버그 버튼) — 초대 vs 숙제 반응 관찰
- **산책 수첩 = 디버그 패널 겸용** ("오늘 5,000보 걸음 (비)" 주입 — Day 1 점화
  시나리오의 목업이기도 함)
- 장면형 업그레이드 3~5종 (전부 % 아닌 장면 변화형)
- 저장/불러오기 (오프라인 경과 포함), 재료 ~10종·레시피 ~8종·손님 ~5종
- **명시적 비구현 (P2로)**: 감쇠, 연료 회계, 푸른불 트리거, 엽서 실시간 지연
  (즉시 지급으로 목업), 업적 실장
- **측정 항목**: 개입 클릭 마모 시점(며칠째 안 누르나) / 초대장 반응(숙제 vs
  초대) / 잉걸불 정서 반응 / 메뉴 미선택 날의 정서(부담 신호 시 주 단위 메뉴로
  완화)

## 8. 기술 계약

- **Godot 4.x** / macOS 우선 개발, Steam 타깃이므로 Windows 병행 검증
- **시간축 계약**: 배달 의례(§3.2) / 맥락 라벨은 폰 캡처 시점 확정 / 걸음
  멱등성 — 시간 버킷 ID 기준 1회 지급 (아이폰+워치 중복, 재설치 대응)
- **⚠️ 릴레이 서버 = 사이클 성립 조건.** 사무실 페르소나(폰 LTE ↔ 회사망 PC)는
  LAN·파일 동기화로 영구히 만나지 못한다 — "아침 개점 개봉"의 물리적 전제가
  서버 경유다. P2 기술 결정 사항 (방식 미정: 최소 저장소 — 계정 → 재료 은행).
  ⚠️ P2를 자기 집 LAN에서만 검증하면 이 구멍이 P3까지 안 보인다.
- **산책 수첩**: 폰 없는 Steam 구매자·접근성 경로 — 명예 기입, 검증 없음
  (무경쟁 게임이라 속여도 자기만 손해). Steam 단독 구매의 완결성 보장.
- **CPU/배터리 초경량**: 상시 실행 전제. 비포커스 시 저FPS·저틱, Godot low
  processor mode — P1부터 습관화
- 상시 저장 (강제 종료 = 퇴근 버튼과 동일 처리의 전제)
- 개발 워크플로우: 아이폰·클라우드(Claude Code) + 맥북 로컬, GitHub 동기화

> 기다리고 있었어요. 편지가 몇 통 와 있어요." — 정산 편지: 약간의 돈 + 근황.
> (산책 한 번 후) "불이 다시 타오르네요! 내일은 급행이 섭니다."
